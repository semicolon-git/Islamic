# PWA (B7)

Installable, offline-capable shell for the beneficiary app. The portal is always network-only.

| Piece | File |
| --- | --- |
| Manifest | `public/manifest.webmanifest` |
| Service worker (hand-written, no build step) | `public/sw.js` |
| Offline fallback (static, EN/AR, no JS bundle needed) | `public/offline.html` |
| Icons, favicon, badge, OG image | `public/icons/*`, generated by `node scripts/make-icons.mjs` |
| Kill switch | `src/features/pwa/kill-switch.sw.js` |
| Client: registration, update toast, install banner, iOS sheet, offline pill | `src/features/pwa/*.tsx`, `use-*.ts` |
| Pure helpers | `src/features/pwa/logic.ts` |
| Strings | `src/i18n/messages/pwa.ts` (`pwa.offlinePage.*` is mirrored in `offline.html`; a unit test keeps them identical) |

`<PwaProvider />` is rendered once in `src/app/layout.tsx`. It also emits the `og:image` / `twitter:image` tags
(absolute URL from `NEXT_PUBLIC_SITE_URL`, else the request host) and a tiny inline script that catches an early
`beforeinstallprompt`.

## Caching strategies (`classifyRequest` in `public/sw.js`)

| Request | Strategy |
| --- | --- |
| Navigations (pages, incl. `/c/*`, `/card/*`) | network-first, 4 s timeout → saved copy → `/offline.html` (if nothing is saved, a slow network is waited for rather than declared offline) |
| `GET /api/concepts` | network-first, 4 s timeout → saved copy |
| `/_next/static/*` | cache-first (content-hashed) |
| `/icons/*`, `/fonts/*` (incl. `hafs.18.woff2`), manifest, offline page | precached on install, cache-first |
| Images, including cross-origin CDN concept images (opaque) | stale-while-revalidate, max 80 entries, non-opaque images over 4 MB skipped |
| Everything else: any non-GET, `/portal/**`, `/api/events`, `/api/session`, `/api/ms/**`, other `/api/*`, RSC (`?_rsc`, `RSC: 1`) requests, `/talk`, `/sw.js` | **not intercepted** — the browser goes straight to the network and nothing is stored |

Cache keys for pages drop `#hash`, `source`, `utm_*`, `fbclid`, `gclid`, `sw` so `start_url=/?source=pwa` finds `/`.
A page is stored only if it is a `200 text/html`, same-origin, not redirected response; a page can opt out with
the response header `x-sw: sw-no-store`.

**Reading a card online makes it available offline.** Full page loads are stored by the navigation strategy. Client-side
(in-app link) navigations don't fetch HTML, so the client posts `{type:"WARM", pages:[url]}` after each route change and
the worker fetches and stores that page. On the first visit the worker didn't exist yet, so the client also warms the
current page and the `/_next/static` assets it already loaded.

## Registration

`swAction()` in `logic.ts`:

- production → register `/sw.js` (scope `/`, `updateViaCache: "none"`);
- development → only with `?sw=1` (remembered in `localStorage["pwa:sw"]`);
- under browser automation (`navigator.webdriver`) → opt-in with `?sw=1` too, so other features' e2e suites and
  their `page.route` mocks never run behind a worker. The PWA e2e opts in explicitly;
- `?sw=0` / `?sw=off`, or a build with `NEXT_PUBLIC_PWA_DISABLED=1` → unregister every worker and delete every
  `say-*` cache.

## Updates

1. Change `public/sw.js` and **bump `VERSION`** (cache names include it; old caches are deleted on activate).
2. Browsers re-check `/sw.js` on navigation and every 30 min while visible (`next.config.ts` serves it `no-store`).
3. The new worker installs and **waits** (no `skipWaiting` in `install`). The page shows "Update available — Refresh".
4. "Refresh" posts `{type:"SKIP_WAITING"}`; on `controllerchange` the page reloads once. "Later" keeps the old version
   until all tabs close.

## Kill switch

A broken service worker is worse than none. If a shipped `sw.js` misbehaves:

```bash
cp src/features/pwa/kill-switch.sw.js public/sw.js   # then deploy
```

Every client fetches the new `/sw.js` on its next navigation (it is never HTTP-cached). The kill-switch worker calls
`skipWaiting()`, deletes all `say-*` caches, unregisters itself and reloads open tabs, which then load from the network
with no worker. It intercepts nothing. To bring the PWA back, restore the real `sw.js` with a **new** `VERSION`.

Lighter options:
- one visitor: open any page with `?sw=0`;
- every visitor without touching `sw.js`: build with `NEXT_PUBLIC_PWA_DISABLED=1` (clients unregister on next load).

Never delete `public/sw.js` outright: a 404 for the script leaves existing workers running until the browser's 24 h
update check gives up on them; the kill switch removes them immediately.

## Install offer

- Chrome/Edge/Android: `beforeinstallprompt` is captured (and Chrome's mini-infobar suppressed); our banner appears
  2.5 s after load, only from the second visit on or on the home page, never on `/snap`, `/welcome`, `/talk`,
  `/inscription` or the portal, never in standalone mode, and not again for 14 days after "Not now".
- iOS (Safari and iPadOS-as-Mac): no install event exists, so the banner's "Show me how" opens a sheet with
  Share → Add to Home Screen → Add.
- In-app browsers (Instagram, Facebook…) get no offer.

## Icons

`node scripts/make-icons.mjs` regenerates everything in `public/icons/` (commit the output):
`icon.svg` (favicon), `icon-192/512.png`, `maskable-192/512.png` (mark inside the 40 % safe zone), `apple-touch-icon.png`
(180), `favicon-32.png`, `icon-48.png`, `badge-96.png` + `monochrome-512.png` (alpha-only), `og.png` (1200×630).
OG text uses the app's IBM Plex Sans Arabic files (WOFF unpacked to TTF in the script) through sharp's Pango/HarfBuzz
text renderer, so «آيات حولك» is shaped correctly; each text block renders in its own process because libvips only
honours the first `fontfile` per process.

## Tests

- `src/features/pwa/sw.test.ts` loads `public/sw.js` and the kill switch in a Node `vm` with an in-memory
  CacheStorage and scripted network (routing table, offline fallbacks, timeouts, caps, never-cache rules, messages).
- `src/features/pwa/logic.test.ts`: registration decision, platform detection, install-offer rules, strings, manifest.
- `e2e/pwa/pwa-sw.desktop.spec.ts`: manifest/icons served, SW controls after reload, offline visited vs unvisited,
  Arabic offline page, card offline, portal never cached, update toast → Refresh, `?sw=0` escape hatch.
  Offline is simulated with `setOffline` **plus** aborting all routes, because Chromium's offline emulation does not
  reliably reach a running worker's own fetches.
- `e2e/pwa/pwa-install.mobile.spec.ts`: install banner timing, prompt, snooze, visit rules, Arabic, iOS sheet.
